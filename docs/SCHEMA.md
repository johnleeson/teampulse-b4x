# Supabase schema (TeamPulse)

Source of truth: copied from `johnleeson/teampulse-app` into [`reference/`](../reference/).  
Do **not** edit the `teampulse-app` clone — it is reference-only.

Tables (Postgres / PostgREST):

## `profiles`

| Column | Notes |
|--------|--------|
| id | UUID (matches `auth.users.id` for real accounts; generated for dummy members) |
| name, avatar | text |
| roles | text[] / json (`ADMIN`, `PLAYER`, `COACH`, `SPECTATOR`) |
| squad_number | int optional |
| preferred_position, secondary_position | text |
| phone, emergency_contact, date_of_birth, medical_notes | text optional |

## `clubs`

| Column | Notes |
|--------|--------|
| id | UUID |
| name, logo, description | text |
| type | `TEAM` \| `SOCIAL` |
| owner_id | UUID → profiles |
| invite_code | text |
| preferred_team_size | 5 / 7 / 9 / 11 |
| preferred_formation | text |

## `club_members`

| Column | Notes |
|--------|--------|
| club_id, user_id | composite key |
| roles | text[] |

## `matches`

| Column | Notes |
|--------|--------|
| id, club_id | UUID |
| title, date, meet_time, kick_off_time, location | text |
| status | `UPCOMING` \| `LIVE` \| `COMPLETED` \| `CANCELLED` |
| competition | `LEAGUE` \| `FRIENDLY` \| `CUP` |
| score_a, score_b | int |
| signed_up_player_ids | uuid[] / json |
| availability | jsonb userId → `CONFIRMED` \| `UNAVAILABLE` |
| opponent_name, is_home | text / bool |
| potm_votes | jsonb (coach / fans / fanCounts / opposition) |
| photo_urls | text[] |
| formation | text |
| lineup | jsonb slotId → playerId |
| team_size | int |
| sub_plan | jsonb `{ matchMinutes, quarters, swaps[], moves[{afterQuarter, slotA, slotB}], layout{slotId:{x,y}}, playTargets, autoGenerated }`. `moves` exchange two slots from that break onward and do not change minutes. `layout` stores display percentages for markers dragged on the sub-plan pitch (shared with the lineup screen). The web app ignores these keys. |
| ai_summary | optional (web only; B4X omits Gemini) |

## `training_sessions`

Apply [`reference/supabase_training_sessions.sql`](../reference/supabase_training_sessions.sql) once in the Supabase SQL editor.

| Column | Notes |
|--------|--------|
| id, club_id | UUID |
| session_date | date |
| trainer_of_week_id | UUID → profiles, optional, one player |
| present_ids, absent_ids | jsonb uuid arrays |
| well_behaved_ids, poorly_behaved_ids | jsonb uuid arrays. A player is in at most one of these |

## `feed_events`

| Column | Notes |
|--------|--------|
| id, match_id, user_id | |
| user_name, type, content | |
| details | jsonb |
| timestamp | timestamptz |

## RPCs / SQL helpers

See `reference/supabase_*.sql` (e.g. `add_dummy_member`). Apply those in the Supabase SQL editor if missing.

## Realtime

`reference/database.sql` configures replica identity + `supabase_realtime` publication for profiles, clubs, club_members, matches, feed_events. B4X v1 uses REST poll/refresh; realtime can be added later.
